# Project Closure Report

## 1. Project Information

| Item | Description |
|---|---|
| Project Name | Retail Order Processing – Business Analysis |
| Project Type | Self-directed Portfolio Project |
| Role | Business Analyst |
| Project Status | Completed – Preliminary Case Study |

## 2. Project Objectives

The main objective of this project was to analyze an existing retail order processing workflow, identify potential business problems, document business requirements, and propose improvement solutions.

The project also aimed to demonstrate the application of Business Analysis techniques throughout the project lifecycle.

## 3. Work Completed

The project was organized into six phases:

| Phase | Completed Activities |
|---|---|
| 01. Project Initiation | Defined project objectives, scope, business context, and stakeholder analysis. |
| 02. Requirements Elicitation | Prepared interview questions, conducted a simulated interview, analyzed the AS-IS process, and identified potential business problems. |
| 03. Requirements Analysis | Documented business rules, functional and non-functional requirements, use cases, and requirements traceability. |
| 04. Solution Design | Conducted Gap Analysis and proposed improvement solutions. |
| 05. Solution Validation & Testing | Prepared test plans, test scenarios, test cases, execution reports, and an issue log. |
| 06. Project Closure | Consolidated project documentation and reviewed project outcomes. |

## 4. Key Deliverables

The project produced the following deliverables:

- Business Context Diagram
- Stakeholder Analysis
- AS-IS Process Analysis
- Root Cause Analysis
- Business Rules
- Business Requirements (FR/NFR)
- Use Case Diagram
- Use Case Specifications
- Requirements Traceability Matrix (RTM)
- Gap Analysis
- Solution Requirements
- Test Plan and Test Cases
- Test Execution Report
- Defect Log

## 5. Key Findings

During the analysis, five potential business issues were identified:

1. Inventory status accuracy and update responsibility are unclear.
2. Delivery information may require repeated updates.
3. The process does not specify how overdue payments are handled.
4. The process does not define a maximum number of delivery attempts.
5. Complaint validation criteria are not clearly specified.

These findings were derived from the existing process model and simulated interview. They should be validated with actual stakeholders before being treated as confirmed business problems.

## 6. Project Limitations

- The project is a self-directed portfolio case study.
- The interview was simulated rather than conducted with actual business stakeholders.
- Proposed solutions have not been validated by a real business organization.
- No TO-BE BPMN diagram was developed.
- No software prototype or working system was implemented.
- Testing was performed through document review and scenario-based evaluation, not actual system execution.
- Several business rules remain pending clarification.

## 7. Lessons Learned

Through this project, I gained practical experience in:

- Understanding and analyzing business processes using BPMN.
- Identifying stakeholders and analyzing their interests.
- Translating business processes into business requirements.
- Writing functional and non-functional requirements.
- Modeling use cases and documenting system behavior.
- Maintaining requirements traceability.
- Identifying process gaps and proposing improvements.
- Designing test scenarios and evaluating requirement completeness.

## 8. Final Conclusion

This project provided an opportunity to apply fundamental Business Analysis techniques to a retail order processing scenario.

Although the project was developed as a simulated case study, it demonstrates a structured approach to business process analysis, requirements documentation, solution proposal, and preliminary validation.

The project serves as a foundation for further development of practical Business Analyst skills.
